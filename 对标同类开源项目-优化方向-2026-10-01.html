一、先给结论

本项目在「AI 智能体交接」这个细分上是同类开源项目里没有直接对标物的开创者：交接就绪度、交接包、8 个多智能体入口文件、MCP 双向读写、脱敏防线、数据自愈，都是周边竞品（Plane/Huly/Vibe Kanban/Kanboard）未覆盖的能力，工程成熟度（595 用例 / 90% 分支覆盖 / 变异探针 / 真浏览器 E2E）也反超多数同级项目。

真正值得补的只有三类：① 与「Agent 执行闭环」的轻量衔接（审查环节）；② 交互体验向 Plane/Huly 看齐（命令面板、持久视图）；③ 开源化最后一步（许可证 + 远程 CI + 英文文档）——第 ③ 项是让它能进入 GitHub 项目语境的硬门槛（目前仓库无远端、CI 从未真实跑过）。

四、可优化方向清单（按价值/成本排序）

1补「审查（Review）」任务状态，衔接 Agent 执行闭环价值：高 ｜ 成本：低 ｜ 来源：vibe-kanban 已验证的需求

vibe-kanban 用「In Review」承接「Agent 干完活等待人验收」这个真实环节；本项目任务状态只有 待办/进行中/已完成/阻塞，Agent 自动分配（P2 已上线）把活派出去后，缺一个「等人工审查」的中间态。建议：状态机加一档「待审查」，详情页展示该任务的 diff/提交链接（git 集成已有只读能力），交接包与监管报告识别该状态。

2把 Ctrl+K 从「搜索」升级为「命令面板」价值：高 ｜ 成本：中 ｜ 来源：Plane / Huly 标配

本项目 Ctrl+K 目前只做全局搜索；Plane 与 Huly 都把它做成命令中心（新建任务/跳转项目/切换视图/执行动作）。建议扩展为：搜索 + 快捷动作（新建项目/任务、复制交接摘要、打开今日待办、导出交接包），统一走现有 data-act 分发，不引入新框架。

3持久化自定义视图（Plane Views 的轻量版）价值：中 ｜ 成本：低

总览已有搜索与状态筛选，但筛选组合不保存；Plane 的「Views」允许把过滤条件固化为可切换视图。本项目数据面已够（状态/优先级/截止/依赖就绪），缺的只是一层「保存筛选 → 命名视图 → 顶部切换」的薄壳，纯前端即可。

4迭代/周期视角：按截止日跨项目聚合成里程碑价值：中 ｜ 成本：中 ｜ 来源：Plane Cycles

已实现任务 due_date 与依赖图，但没有「这一周/这一个月要交付什么」的跨项目聚合视图。建议加一个「周期视图」：按截止日期把各项目任务聚成 周/月 分组、标注逾期与临期——复用现有临期/逾期判定逻辑，不与「今日待办」重复。

5开源化最后一步：LICENSE + 远程 CI + 英文文档价值：高 ｜ 成本：中 ｜ 硬门槛

与 GitHub 项目可比的前提是：① 补 LICENSE（对齐同类生态可考虑 AGPL-3.0 或 MIT）；② 仓库推到远端并让 GitHub Actions 真跑 ci_local.py --with-exe（AGENTS.md 明确写着「CI 一次都没有真跑过」——本地 21 项门禁是全的，只差最后一步远程执行）；③ README 提供英文版，界面可先不做完整 i18n，用「英文 README + 中文界面」起步。

6（不建议现在做）多用户/团队协作/权限

Plane/Huly 的主赛道，但 AGENTS.md 已明确「不是这个项目的赛道」，会破坏单机简洁性与数据不出本机的安全边界。

7（不建议）复刻 vibe-kanban 的 worktree 并行编排

git worktree 隔离、多 Agent 并行执行是 vibe-kanban 的主场，与「交接中枢」定位重合度低；正确姿态是 MCP 互操作协同（本项目上下文包喂给 vibe-kanban 的任务卡），而不是自己再写一套执行引擎。

8（不建议）换存储层（SQLite/PostgreSQL）

性能基线（2026-09-19 复测）已给出触发条件：列表接口日常 >300ms 才考虑，当前几十项目为个位数毫秒。现在换库只引入失效风险、换不来收益——维持整份 JSON + 跨进程锁是正确的。

五、应守住并继续投资的护城河

  • AGENTS.md 标准对齐：2025-12 起由 Linux 基金会 AAIF 托管、全球 6 万+ 开源项目采用；Claude Code 2.1.277（2026-09-28）起也原生支持 AGENTS.md——本项目「8 入口投影」已踩在行业标准上，值得继续跟随规范演进（如嵌套 AGENTS.md 支持）。
  • MCP 双向能力：23 工具 + 脱敏 + 幂等键 + 跨进程锁，同类中只有 vibe-kanban 有 MCP 但方向不同；这是承接「下一代 agent 工具链」的接口位。
  • 脱敏与密钥隔离：送模型前的全路径脱敏、密钥不进项目目录、导出直链仅本机——这三个设计在开源的看板/任务工具里几乎见不到，是差异化卖点。
  • 工程门禁体系：本地 21 项门禁、变异探针 41/41、真浏览器 E2E——转开源后直接成为项目可信度背书。
