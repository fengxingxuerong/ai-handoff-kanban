### 3.1 本轮收尾复验（2026-11-12 晚）

> 结论先给：**本轮 `ci_local` 是 7/8，唯一一条红是 pytest 覆盖率；定性为本机 xdist
> worker 被外部终止导致 coverage 分片丢失，不是代码缺陷。串行复跑 92.23% 全绿，
> 两份冻结自查 11/0 + 10/0。这条红既不能读成「代码退步」，也不能冒充发版判据。**

| 项 | 命令 | 实测结果 |
| --- | --- | --- |
| 全量门禁 | `python scripts/ci_local.py` | **8 步 7 过 1 失败，exit 1**。红的是 `pytest 全量`：覆盖率 22.78% < 90。其余 7 步全绿：探针 **125/125 全杀**（462.1s）、场景 32/32、回归 16 已验 + 2 未验、演练 21/21、实例数据目录自证、体检 14/0、真浏览器 16/0 且零 JS 报错 |
| 并行复跑 | `pytest -q --cov-fail-under 90` | 仍 exit 1 / 14.82%，但日志给出根因：`[gw6] node down: Not properly terminated` → `coverage: failed workers: gw6` → `The following workers failed to return coverage data`。**进度条 100%、915 条用例无一失败、只有 5 条预期跳过**：跑完了，是分片没交回来 |
| 串行复跑 | `pytest -q -n0 --cov-fail-under 90` | **exit 0，TOTAL 92.23%（门槛 90）**，与 06:14 基线逐字一致 → 定性完成：本机 `-n auto` 抖动，非代码问题 |
| 冻结自查 | `scripts/frozen_smoke.py` / `scripts/mcp_frozen_smoke.py` | **11/0 + 10/0**。含「exe 自报版本与构建戳同源」「产物不比源码旧」「内嵌前端与仓库逐字节一致」「25 工具 / stdout 每行合法 JSON-RPC / 中文双向 / 真落盘 / 日志走 stderr」 |

**口径**：发版判据仍以**已发布事实**为准 —— 远端 CI 同一 SHA 两次 `success`
（干净 runner 的 `-n auto` 未崩，含重打包与冻结自查）+ 06:14 本地 `ci_local --with-exe` 14/14。
本轮复验的独立价值是证明：**当前工作区（含探针字节级还原后的源码）与已发布版本一致、
两个本地 exe 仍可服务**。`pytest.ini` 早已记载「本机 `-n auto` 偶发 Windows 文件锁/杀软抖动，
`-n0` 串行全绿」，这次是同一类问题的另一种形状（worker 被终止 → 覆盖率分片丢失，
比当年的 2~4 条假红更响但同因）。原始日志：
`evidence/ci_local-full.log`、`pytest-recheck.log`、`pytest-serial.log`、
`frozen-smoke.log`、`mcp-frozen-smoke.log`。
