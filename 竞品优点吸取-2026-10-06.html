三、十大候选优点的判定

#优点（来源）判定理由 / 触发线
①任务级验收标准 / DoD 清单（Backlog.md）已落地交接质量的直接抓手：「怎么算完成」明示后，待审查→已完成有据可依，接手方有验收清单可照
②旧记录衰减摘要（Beads 语义压缩）已落地AGENTS.md 已承认 journal 是最先撞线的维度；折叠比「截条数」（10-01 悬而未决的方案）更好——治无声丢历史
③记忆时效维度（OKM timeless/dated）已落地「这把 key 用到月底」这类有保质期的事实过期后会当「当前事实」混进交接包，是真实缺陷
④Inbox 式提醒哲学（Multica：需要拍板才 ping）已落地逾期横幅是「广播」，缺的是「只列等人的」；依赖挡住的任务不算（会自然流转）
⑤Skill 包入口（AAIF / Agent Skills 生态）已落地npx skills add 生态起量，第 9 类入口投影成本极低，且复用同一份正文
⑥MCP 工具分档暴露（Task Master 三档加载）暂缓23 个工具可接受、已有只读模式这个可见性开关；分档会带来客户端工具目录漂移风险。触发线：工具数 >30
⑦会话历史全文检索（Wake FTS5 trigram，中文/代码子串）暂缓需要索引层与新存储，本轮超预算；现有「扫描→预览→提炼」覆盖主用法。触发线：会话源文件规模让扫描明显变慢
⑧handoff 引用化（waggle ~30 字节工件引用 token）不吸收交接包是给人+模型读的 Markdown，引用 token 伤可读性；任务 refs 已是「引用而非复制」的雏形
⑨用量记账细化到 run/任务（Multica per-issue 成本）不吸收本板 AI 调用都是看板级（监管/指令/提炼），没有 run 概念，没有可挂的成本对象
⑩agent 执行编排 / 团队协作 / git-worktree / 换存储（Multica、t3code、Beads-Dolt）不吸收维持 10-01 结论与「不要再做的事」清单；「Agents don't need memory, they need documentation」（HN 2026-10）对本项目定位是背书

四、落地明细（每条：设计 → 改动面 → 钉子）

① 任务验收标准 acceptance（对标 Backlog.md 的 DoD）已落地

设计：任务新增 acceptance: list[str]，上限一对数 MAX_ACCEPTANCE_ITEMS=10 / MAX_ACCEPTANCE_TEXT=120（去空去重、非字符串转写保留）。 五个落点缺一不可：交接包 Markdown（- [ ] 清单，已完成的不列）、接手页任务表（☐ 行）、 接手包 slim.acceptance（原样保留不脱敏——接手方要照着验）、 MCP kanban_get_project 任务行下的 - [x]、任务卡 ☑ n 计数徽章。

改动面：app/main.py（TaskIn、clean_acceptance、_sanitize、create/apply_task、 COLLECTION_OPS += acceptance、_build_handoff_markdown、project_context）· app/handoff_page.py · scripts/mcp_server.py（add/update schema、_clean_notes、get_project 渲染）· web/（任务弹窗 textarea、保存/回填、卡片徽章、提示文案）。

钉子：test_p1_absorb.py 6 条（上限/去重/PATCH 增量动词与冲突 400/五处流转/脏数据自愈）+ test_mcp_server.py 1 条（MCP 建任务带验收、超限在回执里说话）+ test_frontend.py 对账（提示数字与后端常量同源、saveTask 真的按行读）+ SCHEMA_VERSION 1→2（slim 加字段，字段集合快照同步）。

② journal 语义压缩（对标 Beads 衰减摘要）已落地

设计：超 MAX_JOURNAL 的最旧条目不再 del 掉，由纯函数 compress_journal() 折成一条摘要放最前：【早期 N 条已折叠】…， folded 计数永远指原始记录数（旧摘要再次溢出时继承累计），正文受 MAX_JOURNAL_TEXT 约束（不会成为新膨胀点），time 是被折区间的首尾日期。 clean_journal() 在读路径做同一件事——导入的脏数据同样折叠。

为什么比 10-01 悬而未决的「截条数」方案好：那条要 MAX_JOURNAL 50→20、 会看不到既有过程记录；折叠只压体量不压脉络，「早期为什么这么改」的证据还在。

钉子：折叠计数/上限内任意溢出量/继承累计 3 条纯函数用例 + HTTP 折叠流转 1 条； 变异探针 journal_fold_dropped（退回丢弃即红）。 教训顺带钉进 AGENTS.md：旧探针 clean_journal_no_cap 盯的代码随本次改动消失， 探针会哑火——「改被探针盯着的代码必须同步改变异表」这句话现在是硬性约定 25 的一部分。

③ 记忆时效 expires（对标 OKM 知识代谢）已落地

设计：记忆可设 expires（只认 YYYY-MM-DD，格式不对留空并提示）。 判定收敛在 _memory_expired() 一处（到期当天仍有效）；四个出口不召回过期记忆： 交接包、接手包（顶层 expired_memory_count 留痕）、AGENTS.md（_project_memories）、 模型简报（_projects_brief）；交接包省几条在正文开头说话；界面划线 + MCP 列表 ⚠️已于…过期 标注；kanban_memory_add 对格式垃圾回执说破 「没认出来，已按长期有效处理」。

钉子：时效边界（昨天过期/当天有效/未设不加键）、坏格式丢弃、交接包排除+留痕、 AGENTS.md 召回排除 4 条；变异探针 memory_expiry_ignored（判定恒 False 即红）。

④ 🔔 待拍板 GET /api/inbox（对标 Multica Inbox 哲学）已落地

设计：跨项目汇总等人的三类——逾期 / 待审查 / 阻塞；一条任务只进一类， 优先级 待审查 > 阻塞 > 逾期；依赖没满足的不算（随前置完成自然流转，那是「今日」的事）、 临期不算（横幅已管）、已完成的绝不在内。前端头部铃铛 + 计数徽标（数量来自同一接口， 不在前端另算一份）+ 分色分组弹窗，点条目跳项目；Ctrl+K 命令面板同款入口。

钉子：三类命中/计数/排序、空看板、脏截止日期绝不判逾期 3 条； 变异探针 inbox_counts_completed（已完成漏进清单即红）。

⑤ 第 9 个入口投影：.claude/skills/ai-kanban/SKILL.md（AAIF / Agent Skills）已落地

设计：AGENT_ENTRY_TARGETS 增加skills 目标，frontmatter name 与目录名同取 SKILL_NAME 一份常量，正文仍是 AGENTS.md 那一份 （投影不是第二份内容）。导出端点本就 mkdir(parents=True)，嵌套路径零改动。

钉子：test_agent_files.py 路径集合 8→9、frontmatter 契约 1 条、 覆盖跳过计数 7→8；界面「其余 7 个都是投影」文案与 README 同步改。

五、明确不吸收与风险警示

  • handoff 引用化 / 用量按 run 记账：理由见表三 ⑧⑨，想清楚了，别再提。
  • MCP 工具分档、会话全文检索：暂缓，触发线写明（表三 ⑥⑦），到线再议。
  • 赛道风险警示：vibe-kanban（28k★）死于无商业模式、Task Master（28k★）四个月停更、 Letta 主仓 24.6k★ 实为壳、记忆层厂商基准第三方复现即跌——星标≠生命力，引用竞品数据必须标注口径。 本项目若开源化需先想清维护策略。
  • 定位背书：2026 年「agent 工作管理」品类爆发（Multica 九个月 52k★、Plane 亲自下场、 153 个新 kanban 编排仓无一超百星）——品类在爆炸但没有整合者， 「交接+记忆+会话+看板」四合一的单机位仍然空着；HN《Agents don't need memory, they need documentation》思潮与本项目「文档/交接包为中心」同向。
