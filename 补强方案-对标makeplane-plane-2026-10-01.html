日期：2026-10-01 对象：AI 交接看板 v1.1.0 性质：补强方案（仅分析，不改代码） 数据：GitHub API 实时抓取 2026-10-01

一、结论速览

plane 是「给人类团队用的全员项目平台」，本项目是「给 AI 智能体交接用的单人看板」——定位不同，但 plane 五个能力点值得吸收。按「成本 / 价值 / 与本项目交接定位的契合度」筛选后，给出 2 项 P0 + 3 项 P1 + 1 项 P2 补强建议，全部落在现有架构的增量扩展上，不改存储模型与既有契约。

🟥 P0 · 立即做

用量与成本看板（数据已有，只差界面）
项目级趋势统计（复用健康预警的既有数据流）

🟨 P1 · 尽快做

可保存筛选视图
交接包模板配置
会话提炼直建任务（打通已有 AI 链路）

🟩 P2 · 可选

里程碑轻量版（不引入完整 Sprint）

⛔ 不建议吸收

多用户权限、工作流引擎、富文本协作编辑、回收站 —— 与本项目"单机交接"定位冲突（详见第七节）

二、plane 核心能力画像

基于 plane README（2026-10-01 抓取）与产品文档，其能力可归纳为六个支柱：

能力plane 的做法对本项目的可借鉴度
Work Items富文本编辑器 + 文件上传 + 子属性 + 关联 issue，任务即内容载体中 —— 本项目任务文本足够，富文本与本项目「上下文可被 LLM 读取」的契约冲突
Cycles（周期/冲刺）按周期组织工作，燃尽图追踪进度低-中 —— 单人看板无团队迭代刚性需求，可降级为「里程碑」
Modules（模块）大项目拆成小模块，模块独立跟踪低 —— 本项目「项目→任务」两级已够，模块= 加中间层，违背精简原则
Views（视图）自定义过滤器组合成视图，可保存、可分享高 —— 本项目有全局搜索但无「保存常用筛选」能力
Pages（页面）AI 能力的富文本页面，笔记可转 issue中 —— 「转行动项」与本项目 AI 指令 ∕ 会话提炼链路天然衔接
Analytics实时洞察、趋势可视化、移除阻塞（blocker）高 —— 本项目已有健康预警 + usage.jsonl 数据，缺的是「可视化面」

另外值得注意的 plane 设计哲学：God mode（实例级配置）、自托管 Docker/K8s、AGPL 开源 + Cloud 商业化 —— 后者正与 vibe-kanban 关停形成对照（见下方第五节风险提示）。

四、补强点清单（可落地，待确认后实施）

P0 补强 1：用量与成本看板

对标：plane Analytics ∕ agent-teams-ai 预算告警　高价值 · 低成本

现状：usage.jsonl 已按端点/模型记账（llm._usage_locked + 裁剪上限 MAX_USAGE_LINES），/api/usage 返回数据，但界面只有数字，无趋势图、无成本维度、无超支感知。

补强内容：新增「用量分析」视图 —— ① 按日/按端点/按模型的调用次数趋势折线（前端原生 SVG，不引第三方库）；② 估算成本（每个端点可配单价，未配则只显示次数）；③ 预算上限 + 阈值告警条（到 80% 变黄、100% 变红，复用 toast 通知）。

项内容改动位置
数据/api/usage 增补按时间聚合字段（或新增 /api/usage/stats）app/main.py（路由层，数据层不动）
界面设置面板新增「用量」Tab：SVG 折线 + 预算条web/（js-core.js 数据、js-render.js 渲染、index.html Tab 注册）
告警阈值判定 + toast() 提示（复用 aria-live 区）web/js-core.js
测试聚合正确性（跨日边界、端点分组）+ 前端静态契约（data-act 注册）tests/（test_usage 或 test_ai 相关）

验收：打开设置→用量 Tab 能看到至少一个端点的趋势折线与次数聚合；预算条随用量变化；无第三方依赖新增。

P0 补强 2：项目级趋势统计

对标：plane Analytics（趋势可视化、移除阻塞）

现状：健康预警已按「代码活动 vs 看板活动」给出结论文案，但只有一句话结论，没有量化图形；任务有状态/优先级/截止日期/依赖，数据全在，只是没有聚合展示。

补强内容：详情页「统计」区 —— ① 每项目任务状态分布（待办/进行中/已完成/阻塞，环形或堆叠条，原生 SVG）；② 截止日期热力（未来 7 天到期 / 已逾期 / 无期限计数）；③ 依赖阻塞链提示（从既有 executable_tasks 反推「被阻塞的任务数」+ 「阻塞了谁」）。

项内容改动位置
数据新增 GET /api/projects/{pid}/stats（聚合计算，纯函数可测）app/main.py 或 new app/stats.py（参考 taskgraph.py 的纯模块拆分方式）
界面详情页新增统计卡片区，SVG 渲染web/（js-render.js + js-data.js + index.html）
测试聚合正确性 + 与 executable_tasks 一致性tests/

验收：任一含 2+ 状态分布的项目，详情页可见图形与数字；阻塞计数与「可执行任务」接口结论一致；接口数字为只读、不含敏感字段。

P1 补强 3：可保存的筛选视图

对标：plane Views（自定义过滤器 → 保存 → 复用）

现状：全局搜索支持关键词/状态/优先级/截止日过滤，但每次都要重输；交接包/列表没有「常用视角」的记忆。

补强内容：把搜索过滤条件组合保存为命名视图（「本周到期」「阻塞中」等），存 projects.json 的 _views（沿用 _client_refs 的「下划线私有键」惯例，进出导出时随全量导出不脱敏即可）；保存后可一键应用、可删除。视图不进 MCP（局部 UI 便利，不值得扩协议面）。

项内容改动位置
数据_views 键 + 增删查接口（GET/POST/DELETE /api/views）app/main.py（走 mutate()，别碰临界区纪律）
界面搜索面板加「保存此筛选」「我的视图」下拉，action 均走 data-actweb/（js-core.js ＋ index.html ACTIONS 表）
测试视图 CRUD + 越权/空名防护 + 前端 data-act 注册tests/

验收：保存一次条件组合 → 重新打开应用 → 一键还原同条件；删除视图无残留；_views 不参与 redact 判定、不泄露密钥。

P1 补强 4：交接包模板配置

对标：plane God mode（实例级配置哲学）＋ Views（可组合）

现状：交接包小节已有 omit_sections（git/journal/memories/refs/done）可裁，但只能整节开关，不能调整顺序、不能加自定义小节、每次都要手动传。

补强内容：① 项目级「交接模板」：记录该项目的常用 omit_sections 与自定义小节顺序（存 projects.json 项目内字段，如 handoff_sections）；② 生成交接包时若项目已配模板则默认应用，界面交接包弹窗显示当前生效顺序，可临时覆盖。

项内容改动位置
数据项目字段 handoff_sections（可选，缺失=默认全节）app/main.py ∕ app/handoff_meta.py（HANDOFF_SECTIONS 顺序化应用）
界面编辑项目弹窗 + 列表项：交接模板选择器web/（js-edit.js）
测试模板应用 ∕ 覆盖 ∕ 字段回填（防「列表回填丢背景」同款事故）tests/

验收：给项目配「只要 git+done」，生成的交接包只有这两节 + 预算说明；改回默认后生成全节；编辑表单从单项目接口回填（第 16 条纪律钉子继续有效）。

P1 补强 5：会话提炼「直建任务」

对标：plane Pages 「将笔记转化为可行动项」

现状：会话捕获→提炼→入库已有（/api/ai/summarize），AI 指令窗也能建任务（batch_ref 幂等键已通），但「提炼出的行动项 → 落到看板」仍是两步手工操作，未打通。

补强内容：提炼结果的行动项卡片增加「建为任务」按钮：一次给多个行动项打勾 → 批量建任务（自动带来源会话标记、可套用依赖关系），复用 batch_ref:{n} 幂等链路保证不重复。

项内容改动位置
数据提炼结果增加 action_items[] 结构化字段 + 批量创建端点app/main.py（mutate_project 内一次建多条，别分次写）
界面提炼结果卡片 + 勾选 + 「建为任务」按钮（data-act）web/（js-data.js、js-render.js）
测试幂等重放不重复建 + 依赖清洗走 fn 内 + 前端注册tests/

验收：一次提炼 → 勾 2 项 → 各建 1 任务（id 不同）；重复提交同一 batch_ref 返回原 id 且不落盘；任务带来源标示。

P2 补强 6：里程碑轻量版

对标：plane Cycles（降级实现，不引入 Sprint）

内容：项目可选填「里程碑」文本字段（如「v1.1 冻结」「上线前」），任务可归入其一；详情页里程碑分组显示 + 简易完成进度条。仅此而已 —— 不做燃尽图、不做周期视图、不做报表面板（避免向 plane 的方向滑成重平台）。

项内容改动位置
数据项目字段 milestones: [{name, done?}] + 任务可选 milestoneapp/main.py（字段白名单扩展，注意 Literal 不适用、走普通字符串校验）
界面弹窗字段 + 详情分组web/（js-edit.js、js-render.js）
测试字段进出 + 交接包是否纳入（可默认不纳入tests/

验收：能建里程碑、能归组、进度条正确；交接包不因本字段变长。

五、实施路线与优先级矩阵

阶段内容预计工作量收益
第一阶段（P0）用量看板 + 项目统计中（各 1 数据接口 + 1 视图）立即获得「看得见的自监管」，与产品定位呼应
第二阶段（P1）保存视图 → 交接模板 → 提炼直建任务中-大日常操作提速 + 交接链路闭环
第三阶段（P2）里程碑小锦上添花，可延后或砍掉
⚠️ 若实施，必须保持的既有纪律（AGENTS.md 硬性约定）：写操作走 mutate() 且 fn 返回 (changed, result)；前端交互一律 data-act 且 ACTIONS 注册；编辑表单从单项目接口回填；新「追加型」字段设上限（视图≦10 个、里程碑≦20 个）；新增业务规则同步往 mutation_probe.MUTATIONS 加探针；跑 scripts/ci_local.py 全门禁。

六、风险与边界（明确不做）

plane 能力为什么不吸收
多人协作/权限体系改变产品定位（单机交接），引入账户与鉴权大改，违背项目赛道（AGENTS.md「不要再做」明确列出）
富文本/文件上传工作项任务文本会被送进 LLM 与交接包，纯文本/结构化是「机器可读」契约的一部分；富文本打破 redact 与提示词对齐
Modules 中间层两级（项目→任务）已够，加层即加维护成本；交接包与拓扑都会变复杂
完整 Cycles/燃尽图单人无团队迭代，降级为 P2 里程碑即可满足绝大部分需求
回收站/软删除「删错了」已由备份/恢复覆盖（约定 4），加软删除= 每条读路径多一个分支
🛑 商业风险提示（来自 vibe-kanban 关停事件）：2026-04-10，vibe-kanban（28.2k star）母公司宣布关闭，原因是「大量免费用户、找不到可持续的商业模式」。plane 之所以活着，靠 AGPL + Cloud 订阅。本方案若落实，也建议同步思考归属：作为个人自用工具不追求增长，或为「脱敏导出/多端同步」设计可收费能力 —— 这与代码补强无关，但决定项目能活多久。
